# git-homework

Домашняя работа по Git: репозиторий, коммиты, README и публикация на GitHub.

## Что это

Небольшой учебный проект на Python с двумя функциями для приветствия и прощания.
Цель репозитория — не сам код, а практика работы с Git: инициализация репозитория,
осмысленные коммиты, привязка удалённого репозитория и оформление README.

В проекте есть:

- `main.py` — функции `greet()` и `farewell()`.
- `.gitignore` — игнорирование `__pycache__`, виртуальных окружений и файлов редакторов.

## Как запустить / проверить

Требуется Python 3.8 или новее. Внешних зависимостей нет.

```bash
python main.py
```

Ожидаемый вывод:

```text
Привет, Git!
Пока, Git!
```

Если в консоли вместо кириллицы видны «кракозябры», это проблема кодировки Windows-консоли.
Запустите со скрытым перенаправлением вывода:

```bash
set PYTHONIOENCODING=utf-8 && python main.py
```

## Что я сделала

1. Создала папку проекта и файл `main.py` с функцией `greet()`.
2. Выполнила `git init` и сделала первый коммит с `.gitignore` и `main.py`.
3. Добавила функцию `farewell()` и вызвала её из `__main__` — второй коммит.
4. Оформила этот `README.md` — третий коммит.
5. Создала репозиторий на GitHub и привязала его как `origin`
   (`git remote add origin https://github.com/melstroy79-creator/Lesson_2_GitHub.git`).
6. Обнаружила, что на GitHub уже есть два коммита с другим содержимым,
   и объединила обе истории через `git merge --allow-unrelated-histories`.
7. Отправила ветку `main` на GitHub командой `git push -u origin main`.

## Что было сложным / что поняла

**Сложным было:**

- Разобраться с облаком Windows: путь к проекту содержит кириллицу и пробелы,
  поэтому команды с `cd` внутри себя ломались. Вышла из этого через
  параметр `workdir`, который передаёт рабочую папку отдельно от команды.
- Кодировка вывода: русский текст в PowerShell 5.1 по умолчанию отображается
  некорректно. Помогла переменная `PYTHONIOENCODING=utf-8`.
- Связка с GitHub: на этой машине не было `gh` и не было сохранённых учётных данных.
- Конфликт при слиянии: на GitHub уже лежали свои коммиты, поэтому истории оказались
  «не родственными». Обычный `git merge` их не объединяет и ругается на конфликт,
  помогает только явный флаг `--allow-unrelated-histories`.
  В `main.py` был конфликт `add/add` — оба файла добавлялись с нуля.
  Решила в свою пользу через `git checkout --ours -- main.py`, потому что
  версия `print("Hello, World!")` — это заготовка, а не результат задания.

**Поняла:**

- Репозиторий — это просто папка `.git`, её можно удалить и получить проект без истории.
- `git add` — не «сохранить файл», а «положить изменения в индекс», то есть в список
  кандидатов на следующий коммит.
- `git commit` сохраняет снимок индекса, а не папку целиком, поэтому в сообщении
  коммита важно писать *зачем* сделано изменение, а не только *что* изменено.
- `git push` без привязанного `origin` падает: сначала нужен `git remote add origin <url>`,
  и только потом отправка ветки.
- Ветка называется `main`, и её нужно явно указать при первой отправке:
  `git push -u origin main`, иначе Git не поймёт, что именно отправлять.
- `.gitignore` лучше добавить в первый же коммит, чтобы служебные файлы
  (`__pycache__`, `.venv`) случайно не попали в историю — исправить историю потом
  сложнее, чем просто не добавить их сразу.
